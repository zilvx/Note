多线程通信与多进程通信有本质区别：**同一进程内的所有线程共享地址空间**，因此它们天然就能访问同一份数据。多线程通信的核心问题不是“如何传递数据”，而是**如何安全地协调对共享数据的访问**，避免竞态条件和数据损坏。

---

### 🧠 根本前提：线程共享地址空间

一个进程内的所有线程共享：

|共享资源|说明|
|---|---|
|**代码段**|所有线程执行同一程序的代码|
|**数据段**|全局变量、静态变量|
|**堆**|`malloc`/`new` 分配的内存|
|**文件描述符**|打开的文件、套接字|
|**信号处理器**|进程级别的信号处理|

每个线程**独有**的：

|独有资源|说明|
|---|---|
|**栈**|局部变量、函数调用链|
|**寄存器**|程序计数器、栈指针等|
|**线程 ID**|内核标识|
|**errno**|线程局部存储|

这意味着：**一个线程修改了全局变量，另一个线程立刻就能看到**。但这种“可见”是不安全的，因为编译器优化、CPU 缓存、指令重排都可能导致意外行为。

### 🔒 核心机制一：互斥锁（Mutex）

互斥锁是最基础的同步原语，用于保护**临界区**——同一时刻只允许一个线程访问的代码段。

**POSIX 线程（pthread）示例：**

c

#include <pthread.h>
#include <stdio.h>
pthread_mutex_t lock = PTHREAD_MUTEX_INITIALIZER;
int shared_counter = 0;
void *worker(void *arg) {
    for (int i = 0; i < 100000; i++) {
        pthread_mutex_lock(&lock);
        shared_counter++;          // 临界区
        pthread_mutex_unlock(&lock);
    }
    return NULL;
}
int main() {
    pthread_t t1, t2;
    pthread_create(&t1, NULL, worker, NULL);
    pthread_create(&t2, NULL, worker, NULL);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    printf("counter = %d\n", shared_counter);  // 期望 200000
    return 0;
}

**C++ 示例（推荐 RAII 风格）：**

cpp

#include <mutex>
#include <thread>
#include <iostream>
std::mutex mtx;
int shared_counter = 0;
void worker() {
    for (int i = 0; i < 100000; i++) {
        std::lock_guard<std::mutex> lock(mtx);  // 自动加锁/解锁
        shared_counter++;
    }
}
int main() {
    std::thread t1(worker), t2(worker);
    t1.join();
    t2.join();
    std::cout << "counter = " << shared_counter << std::endl;
}

**关键点：**

- `lock_guard` 在构造时加锁，析构时自动解锁，异常安全。
    
- 忘记解锁会导致死锁，RAII 是避免此问题的标准做法。
    
- 互斥锁保护的是**数据**，不是代码。

### 📢 核心机制二：条件变量（Condition Variable）

条件变量用于**线程间的等待/通知**。一个线程等待某个条件成立，另一个线程在条件成立时通知它。

**典型模式：生产者-消费者**

cpp

#include <mutex>
#include <condition_variable>
#include <queue>
#include <thread>
#include <iostream>
std::mutex mtx;
std::condition_variable cv;
std::queue<int> data_queue;
bool done = false;
void producer() {
    for (int i = 0; i < 10; i++) {
        {
            std::lock_guard<std::mutex> lock(mtx);
            data_queue.push(i);
            std::cout << "Produced: " << i << std::endl;
        }
        cv.notify_one();  // 通知等待的消费者
        std::this_thread::sleep_for(std::chrono::milliseconds(100));
    }
    {
        std::lock_guard<std::mutex> lock(mtx);
        done = true;
    }
    cv.notify_all();  // 通知所有消费者结束
}
void consumer() {
    while (true) {
        std::unique_lock<std::mutex> lock(mtx);
        cv.wait(lock, [] { return !data_queue.empty() || done; });
        while (!data_queue.empty()) {
            int val = data_queue.front();
            data_queue.pop();
            std::cout << "Consumed: " << val << std::endl;
        }
        if (done) break;
    }
}
int main() {
    std::thread p(producer);
    std::thread c(consumer);
    p.join();
    c.join();
    return 0;
}

**关键点：**

- `cv.wait(lock, predicate)` 会原子地释放锁并等待，被唤醒后重新加锁并检查条件。
    
- 必须用 `while` 或 `wait` 的谓词形式防止**虚假唤醒**。
    
- `notify_one` 唤醒一个等待线程，`notify_all` 唤醒所有。

### 🚦 核心机制三：信号量（Semaphore）

信号量是一个计数器，用于控制对有限资源的访问或实现线程间的简单通知。

**C++20 示例：**

cpp

#include <semaphore>
#include <thread>
#include <iostream>
std::counting_semaphore<3> sem(3);  // 最多允许 3 个线程同时访问
void worker(int id) {
    sem.acquire();  // P 操作，计数减 1
    std::cout << "Thread " << id << " entered" << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(1));
    std::cout << "Thread " << id << " leaving" << std::endl;
    sem.release();  // V 操作，计数加 1
}
int main() {
    std::thread threads[5];
    for (int i = 0; i < 5; i++)
        threads[i] = std::thread(worker, i);
    for (auto &t : threads) t.join();
    return 0;
}

**POSIX 信号量示例：**

c

#include <semaphore.h>
sem_t sem;
sem_init(&sem, 0, 1);  // 初始值为 1，相当于互斥锁
sem_wait(&sem);
// 临界区
sem_post(&sem);
sem_destroy(&sem);

### 🔄 核心机制四：读写锁（Read-Write Lock）

读写锁允许多个线程同时读，但写时独占。适合**读多写少**的场景。

cpp

#include <shared_mutex>
#include <thread>
#include <vector>
#include <iostream>
std::shared_mutex rwlock;
std::vector<int> data;
void reader(int id) {
    std::shared_lock<std::shared_mutex> lock(rwlock);  // 共享锁，允许多个读者
    std::cout << "Reader " << id << " sees size: " << data.size() << std::endl;
}
void writer(int id) {
    std::unique_lock<std::shared_mutex> lock(rwlock);  // 独占锁
    data.push_back(id);
    std::cout << "Writer " << id << " wrote" << std::endl;
}
int main() {
    std::thread r1(reader, 1), r2(reader, 2);
    std::thread w1(writer, 1);
    r1.join(); r2.join(); w1.join();
    return 0;
}

**关键点：**

- `shared_lock` 用于读，多个线程可同时持有。
    
- `unique_lock` 用于写，独占。
    
- C++17 引入 `std::shared_mutex`，之前用 `pthread_rwlock_t`。

### ⚛️ 核心机制五：原子操作（Atomic Operations）

原子操作是无锁编程的基础，适用于简单的计数器、标志位等场景。

cpp

#include <atomic>
#include <thread>
#include <iostream>
std::atomic<int> counter{0};
void worker() {
    for (int i = 0; i < 100000; i++) {
        counter.fetch_add(1, std::memory_order_relaxed);
    }
}
int main() {
    std::thread t1(worker), t2(worker);
    t1.join(); t2.join();
    std::cout << "counter = " << counter.load() << std::endl;  // 200000
}

**内存序（Memory Order）：**

|内存序|含义|使用场景|
|---|---|---|
|`memory_order_relaxed`|只保证原子性，不保证顺序|简单计数器|
|`memory_order_acquire`|读操作，之后的读写不能重排到它前面|读锁|
|`memory_order_release`|写操作，之前的读写不能重排到它后面|写锁|
|`memory_order_seq_cst`|全序，最强的保证（默认）|通用场景|

**无锁队列示例（简化）：**

cpp

#include <atomic>
#include <memory>
template<typename T>
class LockFreeQueue {
    struct Node {
        std::shared_ptr<T> data;
        std::atomic<Node*> next;
        Node() : next(nullptr) {}
    };
    std::atomic<Node*> head;
    std::atomic<Node*> tail;
public:
    LockFreeQueue() {
        Node* dummy = new Node;
        head.store(dummy);
        tail.store(dummy);
    }
    void push(T value) {
        Node* newNode = new Node;
        newNode->data = std::make_shared<T>(std::move(value));
        Node* prevTail = tail.load();
        while (!tail.compare_exchange_weak(prevTail, newNode)) {}
        prevTail->next.store(newNode);
    }
    // pop 略
};

### 🧩 核心机制六：线程局部存储（TLS）

TLS 让每个线程拥有变量的独立副本，避免共享。

cpp

#include <thread>
#include <iostream>
thread_local int tls_counter = 0;  // 每个线程独立
void worker(int id) {
    for (int i = 0; i < 3; i++) {
        tls_counter++;
        std::cout << "Thread " << id << " tls_counter = " << tls_counter << std::endl;
    }
}
int main() {
    std::thread t1(worker, 1), t2(worker, 2);
    t1.join(); t2.join();
}

**输出：**

text

Thread 1 tls_counter = 1
Thread 1 tls_counter = 2
Thread 1 tls_counter = 3
Thread 2 tls_counter = 1
Thread 2 tls_counter = 2
Thread 2 tls_counter = 3

### 📊 各机制对比

|机制|用途|性能|复杂度|
|---|---|---|---|
|**互斥锁**|保护临界区|中等|低|
|**条件变量**|等待/通知|中等|中|
|**信号量**|资源计数、限流|中等|低|
|**读写锁**|读多写少|读快写慢|中|
|**原子操作**|简单计数、标志位|极高|中|
|**无锁数据结构**|高并发队列/栈|极高|高|
|**TLS**|避免共享|极高|低|

### ⚠️ 常见陷阱

1. **死锁**：两个线程互相等待对方持有的锁。避免方法：统一加锁顺序、使用 `std::lock` 同时加多把锁、设置超时。
    
2. **竞态条件**：未保护共享数据导致结果不确定。用 `-fsanitize=thread`（TSan）检测。
    
3. **虚假唤醒**：`cv.wait` 可能无通知返回。必须用谓词或 `while` 循环检查条件。
    
4. **锁粒度过大**：锁住太多代码导致性能下降。应尽量缩小临界区。
    
5. **忘记解锁**：异常或提前返回导致死锁。用 RAII（`lock_guard`、`unique_lock`）。
    
6. **内存序错误**：无锁编程中错误的内存序导致数据不可见。默认用 `seq_cst`，确定后再放宽。
    
7. **ABA 问题**：无锁编程中值从 A 变 B 又变回 A，CAS 误判。用带版本号的指针或 `shared_ptr`。

### 🔗 在 iBMC/Qt 中的实际应用

结合你之前的关注：

- **iBMC 微组件内部**：一个组件（如传感器服务）可能有多个线程：采集线程、处理线程、D-Bus 通信线程。它们之间用互斥锁保护共享数据结构，用条件变量通知新数据到达。
    
- **Qt 跨线程**：`QMetaObject::invokeMethod` + `Q_ARG` 实现线程间方法调用，底层是事件循环 + 队列。
    
- **共享内存 + 多线程**：共享内存区域可能被多个线程读写，需要信号量或互斥锁保护。iBMC 的 `libsomp.so` 中的 `shm_lock_acquire_write` 就是这种场景。
    
- **D-Bus 多线程**：D-Bus 库本身是线程安全的，但回调函数可能在 D-Bus 线程中执行，需要将数据安全地传递给业务线程。

### 💎 总结

多线程通信的核心是**同步**，而非数据传输。因为线程共享地址空间，数据天然可见，但**并发访问**需要协调。基本的同步原语（互斥锁、条件变量、信号量、读写锁）覆盖了绝大多数场景；原子操作和无锁数据结构用于高性能场景；TLS 用于避免共享。选择哪种机制，取决于**共享数据的读写模式、性能要求和复杂度容忍度**。
