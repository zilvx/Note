### 一、基础语法与关键字

**Q1：C 和 C++ 的区别是什么？**

- C++ 是 C 的超集，在 C 的基础上加入了面向对象、泛型编程、异常处理等功能。
    
- C++ 支持函数重载、运算符重载、引用、命名空间；C 不支持。
    
- C++ 的内存管理使用 `new`/`delete`，C 使用 `malloc`/`free`。
    
- C++ 拥有丰富的标准库（STL），C 标准库主要处理字符串、I/O 等。
    

**Q2：指针和引用的区别？**

- 指针是一个变量，存储另一块内存的地址；引用是一个别名，与被引用变量绑定在一起。
    
- 指针可以为空（`nullptr`），引用必须初始化且不可重新绑定。
    
- 指针有自身地址，`sizeof(指针)` 返回指针大小；`sizeof(引用)` 返回被引用对象的大小。
    
- 指针有多级指针（`int**`），引用没有多级引用。
    
- 引用常用于函数传参（避免拷贝）和返回值，使用更安全直观。
    

**Q3：`new`/`delete` 与 `malloc`/`free` 的区别？**

- `new`/`delete` 是 C++ 运算符，`malloc`/`free` 是 C 库函数。
    
- `new` 自动计算所需内存大小并返回对应类型指针，`malloc` 需要手动计算字节数并强转。
    
- `new` 会调用构造函数，`delete` 会调用析构函数；`malloc`/`free` 不会。
    
- `new` 可以重载，`malloc` 不可以。
    
- 内存不足时，`new` 抛出 `std::bad_alloc` 异常，`malloc` 返回 `NULL`。
    

**Q4：`static` 关键字的作用？**

- **静态局部变量**：存储在静态区，生命周期为整个程序运行期，初次执行时初始化一次。
    
- **静态全局变量/函数**：作用域限定在定义所在文件内（内部链接），避免命名冲突。
    
- **静态成员变量**：属于类而非对象，所有对象共享，必须在类外单独定义。
    
- **静态成员函数**：属于类，只能访问静态成员，无 `this` 指针，可通过类名直接调用。
    

**Q5：`const` 关键字的作用？**

- **`const` 变量**：只读，初始化后不可修改。
    
- **`const` 与指针**：
    
    - `const int *p`：指向的内容不可变，指针本身可变（底层 const）。
        
    - `int * const p`：指针本身不可变，指向的内容可变（顶层 const）。
        
- **`const` 成员函数**：承诺不修改成员变量（`mutable` 修饰的除外），可被 `const` 对象调用。
    
- **`const` 引用**：常用于传参，既可接收左值也可接收右值，避免拷贝。
    

**Q6：`constexpr` 的作用？**

- 表示常量表达式，值在编译期即可确定，可用于数组大小、模板参数等编译期上下文中。
    
- `constexpr` 变量必须由编译期常量初始化。
    
- `constexpr` 函数若传入编译期常量实参，可返回编译期常量；否则可作为普通函数运行（C++14 起放松限制）。
    
- 相比 `const`，`constexpr` 保证编译期可求值，更强调编译期计算。

### 二、面向对象

**Q7：面向对象的三大特性是什么？**

- **封装**：将数据和操作数据的方法捆绑在一起，通过访问限定符隐藏内部实现。
    
- **继承**：子类复用父类的属性和方法，实现代码重用和多态的基础。
    
- **多态**：同一接口不同表现。分为编译时多态（重载、模板）和运行时多态（虚函数）。
    

**Q8：多态的实现原理？**

- 运行时多态通过虚函数实现。含有虚函数的类会生成一个虚函数表（vtable），表中存储该类所有虚函数的地址。每个对象包含一个虚指针（vptr），指向该类虚表。
    
- 通过基类指针/引用调用虚函数时，运行时根据 vptr 找到实际对象的虚表，从而调用正确的函数覆盖版本。
    

**Q9：虚函数与纯虚函数的区别？**

- **虚函数**：有实现，子类可选择覆盖。基类指针/引用可调用子类实现。
    
- **纯虚函数**：声明为 `virtual void func() = 0;` 无实现，子类必须覆盖。含纯虚函数的类为抽象类，不可实例化。
    
- 纯虚函数可以定义实现，但只能在派生类中显式通过基类名调用。
    

**Q10：构造函数和析构函数是否可以是虚函数？**

- **构造函数不能是虚函数**：对象创建时虚表尚未完全建立，无法多态。
    
- **析构函数通常应该是虚函数**：当通过基类指针删除派生类对象时，若析构函数非虚，则只会调用基类析构，导致派生类资源泄漏。
    

**Q11：重载、覆盖（重写）和隐藏的区别？**

- **重载**：同一作用域内，函数名相同，参数列表不同（类型、个数、顺序），与返回值无关。
    
- **覆盖（override）**：派生类中重新定义基类虚函数，签名完全一致（含 const 等），返回值可协变（基类指针/引用返回类型相关）。
    
- **隐藏**：派生类定义了与基类同名的函数，只要参数不同或非虚函数，基类同名函数在派生类中被隐藏。可以通过 `using Base::func;` 引入。
    

**Q12：深拷贝和浅拷贝的区别？**

- **浅拷贝**：逐位复制对象成员，若成员是指针，则拷贝指针值，导致两个对象共享同一块内存。析构时可能重复释放。
    
- **深拷贝**：为新对象分配独立内存，并将指针指向的内容完全复制一份，避免资源重复释放。
    
- 自定义拷贝构造函数、拷贝赋值运算符时，必须处理深拷贝（Rule of Three/Five）。

### 三、内存管理

**Q13：堆和栈的区别？**

- **分配方式**：栈由编译器自动分配和释放，函数参数、局部变量等；堆由程序员通过 `new`/`malloc` 手动申请，`delete`/`free` 释放。
    
- **效率**：栈分配快，仅移动栈指针；堆分配涉及系统调用和内存碎片管理，较慢。
    
- **大小限制**：栈较小（几 MB），堆受系统虚拟内存限制，可达 GB。
    
- **生命周期**：栈变量离开作用域销毁；堆变量手动释放前一直存在。
    
- **内存方向**：栈向低地址生长，堆向高地址生长。
    

**Q14：RAII 是什么？应用有哪些？**

- RAII（资源获取即初始化）将资源（内存、文件句柄、锁等）生命周期与对象生命周期绑定：构造函数获取资源，析构函数释放资源。
    
- 应用：智能指针（`unique_ptr`, `shared_ptr`）、`lock_guard`、`fstream` 等。
    
- 优点：异常安全，避免资源泄漏。
    

**Q15：智能指针有哪些？如何解决循环引用？**

- `std::unique_ptr`：独占所有权，不可拷贝，只能移动。轻量级，无额外开销。
    
- `std::shared_ptr`：共享所有权，内部维护引用计数，计数归零时释放对象。
    
- `std::weak_ptr`：弱引用，不增加引用计数，可从 `shared_ptr` 构造。用于解决循环引用：当两个对象互相持有对方的 `shared_ptr` 时，引用计数永远不会归零，改用 `weak_ptr` 打破循环。

### 四、C++11 及新标准特性

**Q16：左值、右值、左值引用与右值引用的区别？**

- **左值**：有标识符，可取地址，表达式结束后仍存在（如变量）。
    
- **右值**：临时对象，不可取地址（如字面量、函数返回临时对象、`std::move` 的结果）。
    
- **左值引用 `T&`**：绑定到左值，不能绑定右值（`const T&` 可绑定右值）。
    
- **右值引用 `T&&`**：绑定到右值，主要用于移动语义和完美转发。
    
- `std::move` 将左值无条件转为右值引用，实现转移所有权。
    

**Q17：移动语义和移动构造函数的作用？**

- 移动构造函数接受右值引用，通过“窃取”临时对象的资源（如指针交换）而避免深拷贝，提高性能。
    
- 移动后源对象处于可析构但未定义的状态（通常指针置空）。
    
- 配合 `std::move` 可以在需要转移资源时调用移动而非拷贝。
    
- 当类有指针成员时，提供移动语义可大幅降低开销。
    

**Q18：完美转发与 `std::forward` 是什么？**

- 完美转发指函数模板将其参数原封不动地（保持左值/右值性、const 属性）转发给另一个函数。
    
- 需要结合万能引用（`T&&`）和 `std::forward<T>` 实现。`std::forward` 根据 `T` 的推导类型进行条件转发：若传入左值则转左值，右值则转右值。
    

**Q19：`auto` 和 `decltype` 的作用？**

- `auto`：让编译器推导变量类型，常用于简化迭代器或复杂模板类型声明。
    
- `decltype(expr)`：获取表达式的声明类型而不求值，常用于模板中推导返回类型。配合 `auto` 实现返回值类型尾置推导 `auto func() -> decltype(...)`。
    
- 区别：`auto` 会去除引用和顶层 const，`decltype` 保留。
    

**Q20：`nullptr` 与 `NULL` 的区别？**

- `NULL` 是宏，通常定义为 `0`，可能引起重载歧义（如 `void f(int)` 和 `void f(char*)`）。
    
- `nullptr` 是 `std::nullptr_t` 类型的字面量，可隐式转换为任意指针类型，不会匹配整型参数，类型更安全。
    

**Q21：Lambda 表达式的基本语法与捕获列表？**

- 语法：`[捕获列表](参数列表) -> 返回类型 { 函数体 }`
    
- 捕获列表：
    
    - `[]` 不捕获任何变量
        
    - `[=]` 以值捕获所有外部自动变量
        
    - `[&]` 以引用捕获
        
    - `[this]` 捕获当前对象指针（C++20 可捕获 `*this` 拷贝）
        
    - 可混合指定 `[a, &b]`
        
- 注意：值捕获在 lambda 定义时固定，引用捕获依赖变量生命周期。泛型 lambda 参数可用 `auto`（C++14）。

### 五、STL 容器与算法

**Q22：`vector` 扩容原理是什么？`reserve` 和 `resize` 的区别？**

- `vector` 底层是连续内存的动态数组。当 `size() == capacity()` 时插入元素会触发扩容：通常以1.5倍或2倍因子分配新内存，拷贝/移动原有元素，释放原内存。
    
- `reserve(n)`：预分配至少容纳 n 个元素的内存，只改变 `capacity`，不影响 `size`，不能直接访问。
    
- `resize(n, val)`：改变 `size` 为 n，若扩大则以 `val` 填充；缩小则丢弃尾部元素，不改变 `capacity`。
    

**Q23：`map` 与 `unordered_map` 的区别？**

- `map`：底层是红黑树，元素按键排序，操作复杂度 O(log n)。
    
- `unordered_map`：底层是哈希表，元素无序，平均 O(1)，最坏 O(n)。
    
- 使用场景：需要有序遍历或范围查询用 `map`；仅需快速查找且不关心顺序用 `unordered_map`。
    
- 自定义类型作为键时，`map` 需定义 `<` 运算符或比较函数；`unordered_map` 需提供哈希函数和 `==` 运算符。
    

**Q24：常见容器的迭代器失效情况？**

- **`vector`**：插入元素若发生扩容，所有迭代器失效；未扩容，插入点之后迭代器失效。删除元素，被删元素及之后迭代器失效。
    
- **`deque`**：头尾插入/删除可能使迭代器失效，但指针/引用有效（除涉及被删元素本身）；中间插入/删除会使所有迭代器失效。
    
- **`list` / `forward_list`**：插入和删除不影响其他迭代器，仅被删元素迭代器失效。
    
- **`set` / `map`**：删除某节点仅使该节点迭代器失效；插入不影响其他迭代器（红黑树节点分散）。
    
- **`unordered_set/map`**：插入若引起 rehash，所有迭代器失效；删除仅被删元素失效。
    

**Q25：`sort` 与 `stable_sort` 的区别？**

- `std::sort`：快速排序实现（内省排序），不保证稳定性，平均 O(N log N)。
    
- `std::stable_sort`：归并排序，保证相等元素的相对顺序不变，通常 O(N log N)，可能需要额外内存。

### 六、多线程与并发

**Q26：`std::mutex` 与 `std::lock_guard`、`std::unique_lock` 的区别？**

- `std::mutex`：互斥量，需手动调用 `lock()` 和 `unlock()`，易出错。
    
- `std::lock_guard`：RAII 封装，构造时加锁，析构时解锁，不可中途解锁，不可移动。
    
- `std::unique_lock`：更灵活，可延迟加锁、提前解锁、尝试加锁，可移动。配合 `std::condition_variable` 必须使用 `unique_lock`。性能稍低于 `lock_guard`。
    

**Q27：`std::condition_variable` 的作用？**

- 实现线程间同步与通信。典型模式：一个线程等待某个条件（调用 `wait`），另一线程修改条件后通知（`notify_one`/`notify_all`）。
    
- `wait` 接收互斥锁和可调用对象（避免虚假唤醒），被唤醒且条件满足后继续执行。
    
- 必须配合 `unique_lock<mutex>` 使用。
    

**Q28：`std::atomic` 是什么？有什么作用？**

- 提供原子操作的模板类型，保证对变量的读-改-写操作在多线程环境下不可分割，无需显式加锁。
    
- 支持 `load`、`store`、`fetch_add` 等操作，可指定内存序。
    
- 适用于计数器、标志位等简单共享变量，性能远超互斥锁。但需注意内存序带来的顺序问题。

### 七、类型转换

**Q29：C++ 四种强制类型转换及用途？**

- `static_cast`：编译期检查的显式转换，用于相关类型间（基本类型、向上转型、void* 转回），不做运行时检查，不安全向下转型。
    
- `dynamic_cast`：运行时检查的多态类型转换，用于父类指针/引用安全转换为子类（向下转型），失败返回 `nullptr`（指针）或抛出 `std::bad_cast`（引用）。要求基类有虚函数。
    
- `const_cast`：移除或添加对象的 `const`/`volatile` 属性。主要用于去掉 const 以传递给只接受非 const 参数的函数，但修改原 const 对象是未定义行为。
    
- `reinterpret_cast`：几乎不做任何检查的二进制位模式重新解释，如整数转指针。极度危险，慎用。

### 八、编译与链接

**Q30：C/C++ 编译过程是怎样的？**

- **预处理**：处理 `#include`、`#define`、`#if` 等指令，展开宏，生成 .i 文件。
    
- **编译**：将预处理后文件转换为汇编代码（.s），进行词法、语法分析、语义优化。
    
- **汇编**：汇编代码转为目标文件（.o/.obj），是机器码但未链接。
    
- **链接**：将多个目标文件和库合并成可执行文件，解析符号引用（重定位）。
    

**Q31：`extern "C"` 的作用？**

- C++ 支持函数重载，编译时会进行名字修饰（name mangling），链接符中包含参数类型信息。C 语言无重载，无修饰或简单修饰。
    
- `extern "C"` 指示编译器，被修饰的代码按 C 语言的链接约定处理，避免名字修饰，从而能被 C 代码调用或调用 C 库。常用于 C++ 调用 C 库或提供 C 接口。
    

**Q32：防止头文件重复包含的方法？区别？**

- `#ifndef / #define / #endif`（传统头文件保护）：依赖宏名称唯一，可跨编译器，但需每次打开文件扫描条件，且可能出现宏名冲突。
    
- `#pragma once`：编译器指令，保证文件只被包含一次，更简洁高效，避免宏碰撞。但非标准（主流编译器均支持），无法针对部分代码段。

### 九、进阶与设计

**Q33：模板特化与偏特化是什么？**

- 模板特化是对特定模板参数提供单独的专门实现。
    
- **全特化**：所有模板参数都给出具体类型。
    
- **偏特化**（类模板支持，函数模板不支持）：仅部分参数特化，或参数形态受约束（如 `T*`）。
    
- 用于优化特殊类型的行为或处理特例。
    

**Q34：可变参数模板如何实现？**

- C++11 起支持。使用 `template<typename... Args>` 声明参数包。
    
- 一般通过递归展开包：定义一个终止函数和一个递归处理函数，利用 `sizeof...(Args)` 获取个数，或使用折叠表达式（C++17）简化。
    
- 典型应用：`make_shared`、`tuple`、`emplace_back` 等。
    

**Q35：单例模式的线程安全 C++ 实现？**

- 利用 C++11 局部静态变量初始化天然线程安全特性（Magic Statics）：
    


```cpp

class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;
        return instance;
    }
private:
    Singleton() = default;
    ~Singleton() = default;
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;
};
```


- 无需加锁，最简洁高效。若编译器未完全支持C++11，则需双重检查锁配互斥锁。
    

**Q36：仿函数（Functor）和 Lambda 表达式区别？**

- 仿函数是重载 `operator()` 的类对象，可携带状态，有类型名，可继承。
    
- Lambda 是匿名函数对象，由编译器生成唯一闭包类型，捕获列表自动生成成员，方便快捷。
    
- Lambda 通常用于简单回调和局部算法；仿函数用于需要复用或复杂状态的场景。性能上两者均可内联，无本质差异。
