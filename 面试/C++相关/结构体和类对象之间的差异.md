## 核心结论：在C++中，结构体和类**几乎一样**

唯一的**语法区别**是：

|特性|`struct`|`class`|
|---|---|---|
|**默认访问权限**|**`public`**|**`private`**|
|**默认继承方式**|**`public`继承**|**`private`继承**|

**除此之外，它们的功能完全等价**：都可以有成员变量、成员函数、构造函数、析构函数、继承、多态、模板等。

---

## 1. 唯一的语法区别（代码验证）
```cpp
// 结构体：默认 public
struct Student {
    int age;        // 默认 public，外部可以直接访问
    void study() {} // 默认 public
};
// 类：默认 private
class Teacher {
    int salary;     // 默认 private，外部不能直接访问
    void work() {}  // 默认 private
};
int main() {
    Student s;
    s.age = 18;      // ✅ OK，public
    
    Teacher t;
    t.salary = 5000; // ❌ 编译错误！private 不可访问
    return 0;
}

```

```cpp
// 继承方式的区别
struct Base { int x; };
struct DerivedStruct : Base { };  // public 继承，x 在 DerivedStruct 中仍为 public
class DerivedClass : Base { };    // private 继承，x 在 DerivedClass 中变为 private
```

---

## 2. 为什么要有两个关键字？（历史与语义）

既然功能一样，为什么C++要保留两个关键字？

### 历史渊源

- **`struct`** 来自 **C语言**，只包含数据，所有成员公开。
    
- **`class`** 是 **C++新增** 的，引入了封装（`private/protected`）和面向对象编程。
    

### 语义约定（程序员之间的默契）

虽然技术上可以混用，但C++社区有一套**默认的语义规范**：

||`struct` 通常用于...|`class` 通常用于...|
|---|---|---|
|**用途**|**纯数据容器**（POD，Plain Old Data）|**完整的对象**（带复杂行为、封装、不变量）|
|**成员**|只有 public 数据，极少或没有成员函数|有 private 数据，丰富的 public/private 成员函数|
|**访问控制**|全部公开，无需 getter/setter|数据隐藏，通过接口访问|
|**例子**|`Point{int x, y;}`, `RGB{uint8_t r,g,b;}`|`std::string`, `std::vector`, `BankAccount`|

**举例：**
```cpp
// 结构体风格：纯数据容器
struct Point {
    float x;
    float y;
    float z;
};
// 类风格：封装了行为和状态
class BankAccount {
private:
    double balance;  // 隐藏数据
public:
    void deposit(double amount) {
        if (amount > 0) balance += amount;
    }
    double getBalance() const { return balance; }
};
```

## 3. 深入：POD类型与平凡类型（与内存对齐有关）

既然你刚学了内存对齐，这里有个重要延伸：

**结构体（特别是POD结构体）的内存布局是确定的**，可以用 `memcpy` 复制，可以和C语言互通。

而**类**如果包含虚函数，内部会多一个**虚函数表指针（vptr）**，内存布局不再"平凡"，不能简单地用 `memcpy` 复制。
```cpp
struct PODStruct {
    int x;
    double y;
};  // 内存布局：x(4) + 填充(4) + y(8) = 16字节，完全确定
class NonPODClass {
    int x;
    double y;
    virtual void func() {}  // 有了虚函数，对象开头多了 vptr（8字节）
};  // 内存布局：vptr(8) + x(4) + 填充(4) + y(8) = 24字节（64位系统）
```

**关键点：**

- 结构体默认情况下是 **POD**（除非加了非平凡成员如 `std::string` 或虚函数）。
    
- 类如果加了虚函数或复杂的构造函数，就不再是POD。
    

---

## 4. 两者能互换吗？（以及为什么不能随意混用）

**技术上可以**，但**语义上强烈不建议**：
```cpp
// 这是合法的，但会引发"风格混乱"
class Point {  // 用 class 定义纯数据
public:
    int x, y;
};
struct Rectangle {  // 用 struct 定义有私有数据的对象
private:
    int width, height;
public:
    int area() const { return width * height; }
};

```

虽然编译通过，但会**让代码阅读者困惑**。社区约定俗成：

- 看到 `struct` → "这是简单数据容器，可以直接访问成员"
    
- 看到 `class` → "这是封装好的对象，通过接口访问"
    

---

## 5. 实战建议（什么时候用谁？）

|场景|推荐使用|原因|
|---|---|---|
|纯数据聚合（如坐标、颜色、配置项）|`struct`|默认 public，访问方便，符合C风格，与C语言交互友好|
|带复杂行为的对象（如银行账户、玩家角色）|`class`|默认 private，强制封装，保护不变量|
|需要虚函数/多态|`class`|语义清晰，表明这是面向对象设计|
|模板参数中的类型|都可以|但通常用 `typename` 代替 `class`|
|继承时|基类用 `class`，派生类用 `class`|除非明确需要 public 继承|

---

## 6. 一个容易混淆的坑：`class` 和 `struct` 的 forward declaration
```cpp
struct Foo;   // 前置声明为 struct
class Foo;    // ❌ 错误！类型不一致，会导致"类型不匹配"错误
```

**规则：** 同一个类型，前置声明和定义必须使用相同的关键字。

---

## 7. 总结（一句话记忆）

> **在C++中，`struct` 和 `class` 的唯一区别是默认访问权限（public vs private）。但约定俗成：`struct` 用于简单数据容器，`class` 用于封装良好的对象。**
