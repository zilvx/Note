### 一、Linux 基础与命令

**Q1：如何查看进程、内存和磁盘使用情况？**

- **进程**：`ps aux`（快照）、`top` / `htop`（实时动态）。
    
- **内存**：`free -h`（物理内存/交换区）、`cat /proc/meminfo`（详细内核内存信息）、`vmstat`（上下文切换、内存页）。
    
- **磁盘**：`df -h`（分区使用量）、`du -sh *`（目录大小）、`iostat`（I/O 统计）。
    

**Q2：硬链接与软链接（符号链接）的区别？**

- **硬链接**：与源文件共享 inode，相当于别名。删除源文件不影响链接，不能跨文件系统，不能链接目录。
    
- **软链接**：独立 inode，存储目标路径字符串。源文件删除后链接失效（断链），可跨文件系统，可链接目录。
    

**Q3：如何查找文件或内容？**

- 文件名查找：`find /path -name "*.cpp" -type f`
    
- 文件内容查找：`grep -rn "keyword" /path`（递归行号），`-i`忽略大小写。
    
- 批量操作配合 `xargs`：`find . -name "*.log" | xargs rm -f`
    

**Q4：标准 I/O 重定向和管道是什么？**

- `>` 覆盖输出，`>>` 追加，`<` 输入重定向。
    
- `2>&1` 将标准错误合并到标准输出。
    
- 管道 `|` 将前一个命令的标准输出作为后一个命令的标准输入，本质通过内存缓冲区传递数据。

### 二、系统编程（C/C++ 与 Linux API）

**Q5：进程与线程的区别？**

- **进程**：资源分配的基本单位，拥有独立的地址空间、文件描述符表等，通过 IPC 通信。
    
- **线程**：CPU 调度的基本单位，共享进程的地址空间和资源，但拥有自己的栈、寄存器，切换开销小。
    
- Linux 内核通过 `clone()` 创建，线程实际是轻量级进程（LWP），可用 `pthread` 库操作。
    

**Q6：多进程的 fork() 行为是怎样的？**

- `fork()` 创建子进程，返回两次：父进程返回子进程 PID，子进程返回 0。
    
- 子进程拷贝父进程的地址空间（写时拷贝）、文件描述符表（共享文件偏移）。
    
- 需注意避免孤儿进程和僵尸进程：子进程结束若父进程未回收（`wait`/`waitpid`）则变成僵尸；父进程先于子进程退出，子进程被 init 收养。
    

**Q7：进程间通信（IPC）方式有哪些？**

- **管道（pipe）**：半双工，亲缘进程间。
    
- **命名管道（FIFO）**：可有亲缘无关，磁盘存在文件节点。
    
- **信号（signal）**：异步通知，如 `SIGKILL`。
    
- **消息队列**：系统 V 或 POSIX，有类型的分组消息。
    
- **共享内存（mmap/shm）**：效率最高，需同步机制（信号量）。
    
- **信号量（semaphore）**：用于进程/线程同步。
    
- **Socket**：可跨网络，也常用于本地通信（Unix Domain Socket）。
    

**Q8：`mmap` 的作用和使用场景？**

- 将文件或设备映射到虚拟地址空间，直接操作内存即可读写文件，减少系统调用和内核缓冲拷贝。
    
- 场景：高效文件 I/O、进程间共享内存、实现动态库加载、内存分配器。
    

**Q9：select、poll 和 epoll 的区别？**

- `select`：有文件描述符数量限制（通常 1024），每次调用需将 fd 集合从用户态拷贝到内核，O(n) 轮询。
    
- `poll`：用链表存储 fd，无数量限制，但仍需拷贝和 O(n) 轮询。
    
- `epoll`：内核维护红黑树和就绪链表，fd 只需注册一次，通过回调将就绪 fd 放入链表，`epoll_wait` 直接获取就绪事件，O(1) 获取。适合高并发。

### 三、多线程与并发

**Q10：线程同步方式有哪些？**

- **互斥锁（mutex）**：确保独占访问临界区。
    
- **读写锁（rwlock）**：允许多读单写，读锁共享。
    
- **条件变量（condition variable）**：配合 mutex 实现等待-通知模型，避免忙等。
    
- **信号量（POSIX sem）**：控制并发访问数量。
    
- **原子操作（atomic）**：无锁，适用于简单计数器等。
    

**Q11：什么是死锁？如何预防和排查？**

- 死锁四必要条件：互斥、持有并等待、不可剥夺、循环等待。
    
- 预防：破坏任一条件，如资源排序锁定（避免循环等待）、`pthread_mutex_trylock` 回退。
    
- 排查：`pstack`/`gdb` 查看线程卡锁位置；`strace -f -p PID` 观察 futex 调用；静态分析工具。
    

**Q12：虚假唤醒是什么，如何处理？**

- 条件变量 `wait` 可能在未被显式通知时返回（POSIX 允许）。
    
- 处理方式：循环检查条件，必须使用 `while (!condition) pthread_cond_wait(...)` 而非 `if`。

### 四、网络编程

**Q13：TCP 三次握手和四次挥手的过程？**

- 三次握手：C->S SYN，S->C SYN+ACK，C->S ACK。同步序列号，建立连接。
    
- 四次挥手：主动方发出 FIN，被动方 ACK；被动方发出 FIN，主动方 ACK。存在 TIME_WAIT 状态（2MSL）。
    

**Q14：TCP 如何保证可靠性？**

- 序列号与确认应答、超时重传、流量控制（滑动窗口）、拥塞控制（慢启动、拥塞避免、快重传、快恢复）、校验和。
    

**Q15：服务端 socket 编程的基本流程？**

1. `socket()` 创建套接字
    
2. `bind()` 绑定地址端口
    
3. `listen()` 开始监听
    
4. `accept()` 接受连接（返回新 fd）
    
5. 使用 `read`/`write` 或 `send`/`recv` 通信
    
6. `close()` 关闭连接  
    客户端只需 `socket()->connect()` 后通信。

### 五、调试与性能分析

**Q16：GDB 常用调试命令？**

- `bt`：查看调用栈
    
- `frame n`：切换栈帧
    
- `info locals/args`：查看变量和参数
    
- `break func/line`：设断点，可加条件 `b 10 if i==5`
    
- `next`（单步跳过）、`step`（单步进入）
    
- `p var` 打印变量，`watch var` 监控变化
    
- 调试 core dump：`gdb ./prog core`，然后 `bt`
    

**Q17：如何定位内存泄漏？**

- **valgrind**：`valgrind --leak-check=full ./prog` 可定位泄漏点。
    
- **AddressSanitizer**：GCC/Clang 编译时加 `-fsanitize=address`。
    
- 查看 `/proc/PID/maps` 或 `pmap` 辅助分析。
    

**Q18：strace 的用途？**

- 跟踪程序发出的系统调用和信号。`strace -f -e trace=network ./server` 只追踪网络调用，快速定位连接、读写问题。
    

**Q19：perf 常用场景？**

- `perf top` 实时采样热点函数。
    
- `perf stat ./prog` 统计 cache-miss、分支预测等。
    
- `perf record & perf report` 生成调用图火焰图分析 CPU 瓶颈。

### 六、编译、构建与库

**Q20：gcc 编译流程？静态库和动态库的区别？**

- 编译四步：预处理 -> 编译 -> 汇编 -> 链接。
    
- 静态库（.a）：链接时复制到可执行文件，体积大，更新需重新编译。
    
- 动态库（.so）：运行时加载，共享内存，可独立更新。编译时 `-l` 指定库，`-L` 指定路径；运行时配置 `LD_LIBRARY_PATH` 或 `/etc/ld.so.conf`。
    
- `ldd` 查看程序依赖的动态库。
    

**Q21：Makefile 中的 `$@`, `$^`, `$<` 是什么？**

- `$@`：目标文件
    
- `$^`：所有依赖文件
    
- `$<`：第一个依赖文件  
    常用于模式规则，减少重复。

### 七、内存管理与内核基础

**Q22：虚拟内存与物理内存的映射？**

- 进程访问虚拟地址，MMU 通过页表将虚拟地址转换为物理地址。
    
- 缺页中断：访问无效/换出内存时触发，内核加载页并更新页表。
    
- `top` 中 VIRT（虚拟内存大小），RES（驻留物理内存），SHR（共享内存）。
    

**Q23：用户态与内核态的区别，如何切换？**

- 用户态权限受限，内核态可访问所有资源。
    
- 系统调用、异常、硬件中断使 CPU 陷入内核态。系统调用通过 `int 0x80` 或 `syscall` 指令触发，传递调用号和参数。
    

**Q24：常见的文件系统 IO 模型：缓冲IO、直接IO、mmap？**

- 缓冲 IO（标准C库）：利用用户缓冲区减少系统调用，有 page cache。
    
- 直接 IO（`O_DIRECT`）：绕过 page cache，降低 CPU 占用但 I/O 必须对齐，用于数据库等自己管理缓存场景。
    
- mmap：映射文件到内存，修改实时反映到 page cache，适合随机读写。

### 八、场景分析与设计题

**Q25：如何实现一个高并发 TCP 服务器？**

- 使用 epoll + 非阻塞 I/O + 线程池/协程。
    
- 主线程 epoll_wait 获取就绪事件，分发给工作线程处理具体业务，避免阻塞事件循环。
    
- 考虑使用 Reactor/Proactor 模式，内存池，连接池等优化。
    

**Q26：系统负载突然飙升，如何排查？**

1. `top/htop` 快速定位异常进程（CPU/内存）。
    
2. `vmstat 1` 查看 r 列（运行队列）、上下文切换和中断。
    
3. `iostat -x 1` 检查磁盘 I/O 是否满（%util）。
    
4. `sar -n DEV 1` 查看网络吞吐和丢包。
    
5. 针对进程用 `strace` 跟踪系统调用，`perf top` 看热点函数，结合日志分析。
    

**Q27：如何处理程序 crash 及 core dump？**

- 确保开启 core dump：`ulimit -c unlimited`，配置 core 文件路径。
    
- 设置 `/proc/sys/kernel/core_pattern`。
    
- 产生 crash 后，用 `gdb program core` 查看崩溃点、调用栈和变量，使用符号调试需编译加 `-g` 且不 strip。
